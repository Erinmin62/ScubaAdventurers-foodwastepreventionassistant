- Inspect my existing code before making changes.
- Do not rebuild the app from scratch or remove existing features.
- Reuse my existing inventory data, expiry analysis, AI recommendations, workflow triggers, approval system and activity log wherever possible.

## 1. Prominent notification indicator

Add a clearly visible notification bell icon in the main navigation or dashboard header.

Requirements:
- Display a noticeable badge showing the number of unread notifications.
- Update the count automatically when new notifications are generated.
- When the user opens the app, show a prominent notification summary if unread or critical notifications exist.
- Do not display an intrusive popup every time the user navigates between pages. Show the summary once per session or when genuinely new critical notifications arrive.
- Clicking the bell opens the notification centre.
- Ensure the unread count remains accurate after refreshing the page or signing in again.

Example:
🔔 Notifications (5)

"5 notifications require your attention:
- 2 items approaching expiry
- 1 critical expiry risk
- 2 actions awaiting approval"

These counts must come from actual application data, not hardcoded examples.

## 2. Notification centre

Create a clear notification panel or dedicated page with:
- Notification title and description.
- Severity indicator: Critical, Warning, Info or Success.
- Related inventory item or workflow action.
- Date and time.
- Read/unread status.
- A clear action button such as "View Item", "Review Action" or "View Details".

Include:
- Mark as read.
- Mark all as read.
- Filter by All, Unread, Critical, Expiry and Pending Approval.
- Dismiss notifications when appropriate.
- Navigate directly to the relevant inventory record or workflow action when a notification is clicked.

Make unread notifications visually distinct using a background highlight, bold title or unread dot. Do not rely on colour alone.

## 3. Food expiry notifications

Connect notifications to the existing inventory and expiry analysis.

Use configurable thresholds with these sensible defaults:
- Critical: expires today or is already expired.
- Warning: expires within 3 days.
- Upcoming: expires within 7 days.

For each relevant item, show:
- Food or inventory item name.
- Quantity and unit.
- Expiry date and remaining days.
- Estimated inventory value at risk when cost data is available.
- Recommended next action.

Example:

"⚠️ Milk approaching expiry"

"8 cartons expire in 2 days. Prioritise safe use of this stock and review upcoming replenishment."

Button: "View Inventory"

Requirements:
- Prioritise critical risks at the top of the notification centre.
- Update or resolve alerts when inventory changes.
- Avoid creating duplicate notifications every time inventory analysis runs.
- Do not recommend consuming or selling expired food.
- Never claim food is safe based only on appearance or smell.

## 4. Workflow and approval notifications

Connect the notification system to the actual ExpiryGuard AI workflow.

Create notifications when:
- An AI analysis identifies a significant food waste risk.
- A prevention recommendation requires the owner's attention.
- A supplier order adjustment or another consequential action awaits approval.
- An action succeeds.
- An action fails or requires manual intervention.

Example:

"📋 Supplier order approval required"

"ExpiryGuard AI recommends reducing the next order from 20 cartons to 8 cartons based on current stock and expected incoming deliveries."

Buttons:
- "Review Action"
- "Approve"
- "Reject"

Approval and rejection must be securely validated on the server. If confirmation is needed, show a confirmation dialog before proceeding.

Important:
- A notification must never approve or execute an action just because it was displayed or opened.
- Rejecting an action must not execute it.
- Approving an action should execute the existing simulated workflow and record the outcome in the activity log.
- Update the notification status when the action is completed, rejected or no longer requires attention.

Avoid unnecessary animations, excessive popups or clutter.

## 6. Notification automation and lifecycle

The notification system must be connected to actual application events rather than displaying static sample notifications.

Requirements:
- Generate alerts when inventory analysis detects relevant risks.
- Generate approval notifications when workflow actions require user decisions.
- Update notification records when inventory, expiry dates or workflow status changes.
- Persist notifications in the existing database or storage system.
- Maintain accurate unread counts.
- Prevent duplicate alerts for the same unresolved event.
- Use stable identifiers or deduplication logic.
- Distinguish unread/read status from action status. Marking a notification as read must not automatically resolve an expiry risk or pending approval.
- Resolve or update stale notifications when the underlying condition is no longer relevant.
- Handle missing or invalid inventory data gracefully.
